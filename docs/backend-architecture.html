And here is where the chain stops. After apply, the episode is stored and can be retrieved again — but there is no arrow from the outcome to a lesson. No consolidate, no learn. The loop can notice; it cannot generalise.

3 · Your chat, precisely

You asked how your chat reaches the agent. It is worth being exact, because it is easy to assume it is a debugger and it is not.

YOU TYPEchat pane, bottom right
→
POST /api/chatserver.py:167
→
becomes an utterancesomething the agent must answer
→
the agent repliesin its own words, next beat
Why this matters for the science. Your message enters the prompt as something the passenger heard, not as a state override — so the agent has to decide what to do about it, and its answer is a genuine reaction rather than a switch being thrown.
But there is only one chat channel, and you should know it. I had assumed the experimenter probe was separate from the participant chat. It is not. __EXPERIMENTER_CHAT__ is a JavaScript shim (src/cognitive.js:1255) that proxies to the same /api/chat endpoint — it only differs by being a synchronous XHR, for compatibility with the old hook shape. Its own comment says the reply is chosen by mind.chat_send() on the server.

So an experimenter probe and a participant utterance are indistinguishable to the agent. That is fine while you are just watching. It is a serious confound the moment you probe during a measured ride — the agent has no way to treat an instrument reading as different from the passenger hearing something. Worth separating before any human data.
