01Why a language model needs an architecture

A language model is a function. You hand it a prompt, it returns text. That is genuinely all it is — and on its own it has three problems that matter for anything you want to call an agent:

  1. It forgets. Whatever happened two turns ago is gone unless you pasted it back in.
  2. It cannot accumulate. Nothing it learned on Tuesday exists on Wednesday.
  3. It has no insides. You cannot inspect why it decided what it decided, so you cannot argue with it.

A cognitive architecture is the answer to those three: decide what the agent remembers, where that memory lives, and what the model is allowed to see on a given turn. The model stays a function. The architecture is the scaffolding around it — and it is scaffolding you can read, test, and disagree with.

The one test that separates an agent from a clever prompt. If you delete the architecture and replace it with one enormous system prompt, does behaviour change? If not, you had a prompt. If yes, you had an architecture — and you can find out which part did it.
02CoALA in one page

CoALA — Cognitive Architectures for Language Agents, Sumers, Yao, Narasimhan & Griffiths, arXiv:2309.02427 — is a framework, not a product. It makes one proposal: a language agent's memory is four interacting systems, and the agent's internal actions are reasoning, retrieval and learning.

SystemWhat it is forWho writes to it
WorkingActive variables for the current decision cycle. Persists across LLM calls — the same context object is reused, not rebuilt from nothing. Everything, constantly
EpisodicExperience from earlier decision cycles. Retrieved into working memory during planning.The agent, by living
SemanticKnowledge about the world and about itself. Traditionally initialised from an external database. Designer seeds it; the agent may add
ProceduralHow to act: implicit (the model's own weights) plus explicit (the agent's code, prompts, rules). Designer only. The paper is explicit that writing here is the risky path

Two sentences from the paper carry most of the design, and both are worth quoting because they are the difference between an agent and a chatbot:

"Working memory ... is a data structure that persists across LLM calls. On each LLM call, the LLM input is synthesized from a subset of working memory." "While learning new actions by writing to procedural memory is possible, it is significantly riskier than writing to episodic or semantic memory, as it can easily introduce bugs or allow an agent to subvert its designers' intentions."

The second sentence is why our procedural memory has no write path at all — not because we forgot, but because the paper tells us not to.

The short answer to "overlapping or contradicting?" — overlapping on architecture, contradicting on retrieval. The four-way decomposition, the working-memory interface, episodic retrieval and the procedural caution are all the literature's, and a reviewer will accept them as such. The retrieval scoring is ours, and it does not match the paper it is usually cited alongside. Two of nine rows are absent.
04Our code: one beat, end to end

Three functions, called in this order, every decision beat. This is the whole loop.

1 · Before the call — build what the model will see

def compose(self, now, state_text, situation_text, budget=6):
    # the "query" is just: where the seat is + how it feels
    query = "%s %s" % (state_text or "", situation_text or "")
    episodes = self.episodic.retrieve(now, query, budget=budget)
    return {
        "episodes":      episodes,                 # ← episodic
        "episodes_text": self.episodic.render(episodes),
        "body":         self.semantic.body_line(),  # ← semantic, SELF
        "world":        self.semantic.render(),          # ← semantic, WORLD
        "vocabulary":   self.procedural.render(),      # ← procedural
    }

Four lines of retrieval, four memories in, one dict out. Note that everything the model ever knows arrives through this function — there is no other path. That is the discipline that makes the experiment auditable: if it is not in this dict, the model did not know it.

2 · The call — the model decides

CoALA is silent about who decides. We decided the model does, and this line is the whole of that decision — note that it returns, so the rule-based code below it becomes unreachable whenever a model is present:

if self.reasoner is not None:
    self._llm_cycle()
    return          # ← the rules argmax below is UNREACHABLE

best, best_v = None, 0.0
for goal in GOAL_CD:          # ← only runs in rules mode

cognition.py:887. Without that return the agent would be a formula with a personality. With it, the model is the only decider and Python supplies only the body and the safety clamps.

The persona carries a body block — height, mass, build, leg length, torso, known conditions — and body_line() turns it into one plain fact line with no conclusions attached. That is deliberate and was corrected once already: an earlier draft told the model that a person with a back problem "usually wants the middle". That hands over the very judgement the experiment is trying to measure. The model gets the fact and works out the rest.
05Retrieval: where we contradict the literature

CoALA does not specify how to retrieve. The convention comes from Generative Agents (Park et al. 2023), which scores every episode on three things and sums them equally:

score = recency + importance + relevance # all normalised 0..1, equal weight

Ours weights them. The three constants are at memory.py:57-59:

W_RECENCY = 0.40 # how recently it happened W_IMPORTANCE = 0.40 # how much it mattered W_RELEVANCE = 0.20 # does it match the current question RULE_IMPORTANCE_FLOOR = 0.85 # a clamp or refusal is important by construction RECENCY_HALF_LIFE = 120.0 # "memory halves every two minutes" RETRIEVE_BUDGET = 6 # episodes the model may see per beat

One of those is a good idea; two are assumptions

RULE_IMPORTANCE_FLOOR solves a real problem: the model grades its own homework, and in a live run it nominated its own episode at 1.00. Letting a rule mark clamps and refusals important regardless is the correct fix.

RECENCY_HALF_LIFE = 120.0 is different in kind. It asserts that memory fades on a particular schedule. Nobody here has evidence for that number. It is a plausible guess wearing a citation, and it should be treated as a variable to measure, not a constant to inherit.

The relevance term has a bug, not a preference

def _relevance(ep, query_tokens):
    ep_text = " ".join(str(ep.get(k) or "")
               for k in ("what", "kind", "intend", "say", "reconsider"))
    overlap = _tokens(ep_text) & query_tokens
    return min(1.0, len(overlap) / max(1.0, len(query_tokens)) * 3.0)

Two things are wrong, and the second is the serious one:

  • The × 3.0 is invented. Nothing in CoALA or Generative Agents suggests it.
  • Dividing by the query length means a longer question is systematically less likely to retrieve anything. Pure artefact of the formula, not a preference.

Together they produce a concrete, checkable failure: ask "what did you do about your back" and a recline episode will not surface, because back and recline share no tokens. Semantic search fixes this and is the honest next step.

Claim discipline. "We implement CoALA's memory decomposition" is true and citable. "Our retrieval follows Generative Agents" is not quite true — it is their triple with our weights and a lexical scorer. Under review, the second claim comes apart. Write it the first way.

Two of these deserve a note. Quiet beat and stay look identical from the outside — nothing happened — which is why every beat is now labelled stay / acted / quiet. Without that, a run that held still forty times and a run where the model was only asked ten times produce the same trace. Condition is the mechanism that turns authored prose into an experiment: a run that logs which conditions were on is reproducible, and a run that does not is an anecdote.

07What is ours, not theirs

Everything above describes what we borrowed. This is what we decided, and a reader who stops here should know exactly where the line is.

1 · The model is the only decider

CoALA is a memory and action-space framework. It does not propose that the language model should make every decision, and anyone citing CoALA for that is stretching it. We made that call, and we made it against a rule-based controller we already had working. The price is in §5: our decision rate is roughly one beat in twenty-five, so "the model is the brain" is true for about 4 % of steps.

2 · No pre-set psychology

The earlier version of this mind carried hand-weighted comfort and trust formulas, attitude tables encoding "38 cm is best", and a suspicion threshold. All gone from the production path. The model receives raw physical truth only — current axis values, the body, the world prose — and decides. What survives from the old system is a rules mode that still runs as a declared baseline for comparison.

3 · Nothing is learned

Episodic memory grows; nothing is consolidated, summarised, or written into semantic memory. The honest description of this system is a reader with a very good memory of one conversation, not a learning agent. CoALA's learning actions are the most obvious thing missing, and the 2026 position paper on episodic memory argues it is also the most valuable thing to add next.

4 · The authored world is a variable, and we are its author

The eight files in prompts/seat/ are the world's only description to the model, and they are written by the same person who wrote the persona and built the rig. That is a genuine confound: the agent may be fitting one person's theory of comfort rather than reasoning about a body. The withhold switch per condition is the mitigation — it makes the authored content something you can ablate rather than a constant you asserted. The A/B is the experiment; the prose is only the starting point.

Where to read next

  • CoALA — arXiv:2309.02427. §4 memory, §4.3 retrieval, §4.5 learning. The only paper here you must read in full.
  • Generative Agents — Park et al. 2023. The recency/importance/relevance triple we borrowed and then re-weighted.
  • Episodic Memory is the Missing Piece for Long-Term LLM Agents — arXiv:2502.06975. The argument for adding consolidation next.
  • Ullman & Malle (2019), the MDMT — the trust instrument, 16 items, four subscales. Note the caveat: it measures trust in robots, and we point it at a car.
  • This repository's docs/REFERENCES-v3-memory-and-trust.md — the full citation spine, including the instrument problem and its alternatives.
If you remember one thing. The architecture is borrowed and citable. The retrieval scoring, the decision policy, and the fact that nothing is learned are ours, and two of the three constants we added are guesses. That is a defensible position — provided it is stated rather than implied.
