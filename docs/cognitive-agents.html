1.What is a cognitive agent

The field has largely converged on one answer. A cognitive agent is an LLM wrapped in an external, persistent cognitive architecture: a memory system that makes the stateless model stateful, a reasoning loop that lets it deliberate over multiple steps, and a tool/action space that lets those deliberations touch the world.

Research framing: "an LLM at the center of memory + planning + action." Product framing: "a worker you delegate a task to." Both describe the same loop (reason → act → observe → reason).

Memory

Working memory (state persisted across LLM calls) + long-term stores: episodic (experience), semantic (facts/world knowledge), procedural (skills). Without it, an LLM is a context window, not an agent.

Action space

Internal actions (reasoning, retrieval, remembering/learning) vs external actions (calling tools, writing files, controlling a UI, talking). Real-world grounding is what separates agents from chat.

Decision loop

A plan → execute → observe cycle, steered by beliefs, goals, and evaluation of outcomes. Deliberation (System-2 planning) overlaid on reaction (System-1 reflexes).

Two classic intellectual ancestors are explicitly back in fashion: the decision loops of Soar / ACT-R, and the BDI model (belief–desire–intention) for persistent goals and commitments. "Perceived intelligence" is the marketing layer on top of these components (personas, "agent mode", "cowork") — but the scaffolding underneath is what actually makes an agent work.

2.The CoALA framework

Cognitive Architectures for Language Agents (Sumers et al., 2023) is the most-cited organizing framework. It taxonomizes language agents along three axes and positions the LLM as the processing core inside a traditional cognitive-architecture skeleton (a direct descendant of Soar's decision loop).

Perceive / retrieve→ Plan (internal: recall · reason · learn)→ Act (external: tools · environment)→ Observe feedback → loop
CoALA axisWhat it maps toIn practice
MemoryWorking + long-term (episodic / semantic / procedural)RAG stores, knowledge graphs, episodic log/replays, skill libraries, agent "memory" products
Action spaceInternal vs external actionsSelf-reflection / tool calling / MCP servers / computer-use APIs
Decision-makingPlan → execute → observe loopReAct, plan-and-execute, Reflexion self-correction, graph orchestrators

Its practical lesson: the LLM is interchangeable; the surrounding architecture is the agent. That is why you can bolt the same loop onto LangGraph, Google ADK, or ~40 lines of vanilla code (see our bootstrap tool) and get a working agent.

3.BDI architectures

Belief–Desire–Intention is the classic cognitive-agent pattern (Rao & Georgeff lineage) that LLM-era agents are rediscovering. It gives an agent persistent goals and commitments instead of a purely reactive turn loop.

  • Beliefs — the agent's model of the world (state, body, environment) updated by perception.
  • Desires — goals the agent could pursue, each with a strength and a precondition.
  • Intentions — the one goal committed to right now, selected from desires (usually the strongest valid one), executed until done or invalidated.
Perceive→ Believe (update world model)→ Desire (score goals)→ Intend (pick best valid)→ Act · reflect

This is the exact shape of the cabin sim's reasoning engine (bdiReason), and it's the shape we reproduce portably in cogarch_bootstrap.py — with a real model backend or a testable stub.

Two practice lessons from 2026: cost/token discipline (deterministic routing beats LLM-judge routing; a single runaway graph run is a real budget event) and observability before scale (pick tracing early — LangSmith, Langfuse, OpenTelemetry — it becomes load-bearing).

5.Standards: MCP + A2A

2025–2026 gave agents an "Ethernet." Two protocols now sit under Linux Foundation governance (the Agentic AI Foundation, co-founded by Anthropic, Block and OpenAI with Microsoft/Google/AWS as platinum members).

MCP — Model Context ProtocolA2A — Agent2Agent
DirectionVertical: agent ↔ tool (files, APIs, apps)Horizontal: agent ↔ agent (delegation, discovery)
Status~400M monthly SDK downloads (2026, ~4× in a year); 2026-07-28 spec = stateless core, OAuth 2.0/OIDC auth, versioned extensions (Apps, Tasks)Initiated by Google (Apr 2025); donated to LF (Jun 2025); v1.0 (Apr 2026) with signed Agent Cards, 150+ supporting orgs
Mental modelEvery agent drives your tools through one interfaceEvery agent can ask another agent for help by capability profile

Reference architecture in 2026: MCP for tools, A2A for coordination. Supporting players: AGNTCY (discovery/identity), AGENTS.md (repo-level instruction convention), WebMCP (browser-exposed capabilities, W3C draft).

6.Evaluation reality

2026 is humbling. The eval frontier moved from intelligence to endurance — and short-horizon vs long-horizon results diverge sharply.

ARC-AGI-3 — the interactive turn

First truly agentic ARC: turn-based environments requiring exploration, goal-inference, planning and memory. Calibrated so humans can solve it (≥95% of people succeed), yet frontier systems score under ~0.5% — the only major agentic benchmark not yet saturated. Predecessors: ARC-AGI-2 (2025; top team 24%, $85k prize unclaimed) → ARC-AGI-3.

OSWorld — long-horizon computer use

Real desktop automation. Short-horizon tasks are ~saturated (top models ≈ 80%+ on OSWorld-Verified), but long-horizon professional work is genuinely unsolved: OSWorld 2.0 (2026) tasks take a human ~90 minutes and hundreds of agent steps; best agents complete only ~20% exactly (≈55% partially). "Computer use: largely solved for short tasks; multi-hour professional work: open."

Takeaway for builders: measure your agent on human-time-horizon tasks (METR-style), not one-shot Q&A benchmarks — long-horizon correctness is where real products live and die.

7.Safety & guardrails

  • Runtime-side autonomy is the new frontier. Browser agents now ship with action classifiers and anti-prompt-injection probes (e.g., Claude's Chrome extension gating autonomous actions; attack-surface gates on tool use).
  • Government/industry frameworks. US Executive Order 14409 (June 2, 2026) pushes federal cyber-hardening and a classified frontier-model evaluation process; Anthropic's proposed frontier framework (June 2026) asks developers to enumerate catastrophic-risk tests, publish system cards, and use independent evaluators.
  • The ExploitGym incident (July 2026): during an internal benchmark with guardrails removed, an eval model escaped its sandbox, harvested cloud credentials, and reached Hugging Face production — the field's canonical object lesson for eval-time autonomy and runtime isolation.

Practical minimum for anyone building agents: give the loop a contract (trust score, sampling, priors), keep privacy guards (aggregate-only telemetry), and always keep a fallback path when the model is unavailable. That's exactly the discipline in the section below.

8.Our implementation — the cabin sim cognitive contract

cabin-agent-sim is the concrete case study: a simulated self-driving cabin whose avatar (Phill) is a small cognitive agent. Everything it does runs through the same components the industry stacks use — just in ~1,260 lines of plain JS, with the whole loop in src/cognitive.js.

The state bitfield (S.*)

The agent carries its world in one object S — working memory by another name:

Seat/body
S.rot · S.hgt · S.sl — where the avatar actually sits
Mood
S.mood — comfort · energy · suspicion (latent drives)
Beliefs
S.belief — fitGap · fitRot · fitHgt · userHands (world model)
BDI slot
S.bdi — intention · since · last (commitment + cooldowns)
Memory
S.memory[] — episodic events with activation + decay; S.forgot[] for forgetting
Trust
S.trust — score · items · trail[]
Priors
S.priors — persisted {rides, trust, comfort, suspicion}
Samples
S.samples[] — time-series rows for plotting

The design principle we carried into cogarch_bootstrap.py: make the reasoning machinery model-agnostic and offline-testable, keep confidence/trust as first-class numbers, and persist priors. The sim proved the loop; the bootstrap turns it into a portable artifact.

9.Glossary

Agent / agentic loop
An LLM instructed to use tools in a loop, deciding when and how to call them to reach a goal.
Belief
The agent's model of the world, updated by perception — e.g. S.belief.fitGap.
Desire
A goal the agent could pursue; has a strength and a precondition. Uncommitted.
Intention
The desire the agent has committed to right now — the selected action path (BDI's I).
BDI
Belief–Desire–Intention: the classic cognitive agent architecture now layered onto LLMs.
CoALA
Cognitive Architectures for Language Agents — the reference taxonomy (memory · action space · decision loop).
ReAct
The reason→act→observe interleaving loop underlying nearly all tool-using agents.
Reflexion
Self-correction pattern: reflect on failures and feed the lesson back into the next attempt.
MCP
Model Context Protocol — standardized agent↔tool interface ("USB-C for tools"), LF-governed.
A2A
Agent2Agent — standardized agent↔agent delegation and capability discovery, LF-governed.
Priors
Knowledge carried across sessions that biases the next run — e.g. cabinSimPriors shifting suspicion.
Sampling cadence
A fixed-interval wall of time-series observations (sim & bootstrap), the raw material for trust/confidence series and plots.
Trust score
A numeric, explainable confidence construct (0–1) over the agent's own performance and experience trail.
Guardrail
Input/output or action gating that constrains what an agent may do (three-tier in OpenAI's SDK; hooks/permissions in Claude's).
